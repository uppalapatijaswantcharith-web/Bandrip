# BANDRIP — client prototype

Immersive website prototype for BANDRIP, a unisex streetwear label with a modelling studio. Django serves the pages; Three.js, GSAP/ScrollTrigger and Lenis drive the 3D and motion; Vite bundles the frontend.

**This is a presentation prototype.** Photography is temporary stock, product names and specs are demo data, store and contact details are placeholders, and the forms validate input but send nothing.

## Run it

Requirements: Python 3.11+, Node 20+.

```bash
pip install -r requirements.txt   # Django is the only runtime dependency
                                  # (requirements-assets.txt adds the asset-pipeline tools)
npm install
npm run build                     # bundles frontend/ into static/dist
python manage.py runserver        # http://127.0.0.1:8000
```

Live-reload development: run `npm run dev` in one terminal and `VITE_DEV=1 python manage.py runserver` in another (PowerShell: `$env:VITE_DEV=1; python manage.py runserver`).

Useful URL flags: `?nogate` skips the intro gate, `?nowebgl` forces the no-3D fallback. The gate shows once per browser session; close the tab or clear session storage to see it again.

Verification (server must be running): `npm run verify` writes screenshots and `verify-output/verify-report.json`.

## Deploy to Vercel (custom .store domain)

The repo is ready for Vercel as-is:

- `api/index.py` runs Django as a single Python serverless function.
- `vercel.json` runs `npm run build:vercel` (Vite build, then `static/` is copied to `public/static`), so images, 3D models and the JS bundle are served from Vercel's CDN; every other path is rewritten to Django.
- `.vercelignore` keeps the 340 MB `assets_src/`, `tools/` and planning docs out of the upload.
- On Vercel, `DEBUG` is off by default, `*.vercel.app` plus the project's production domain are allowed hosts, and HTTPS is detected through `X-Forwarded-Proto` (needed for the CSRF check on the forms).

Steps:

1. Push this folder to a GitHub repo (or run `npx vercel` from this folder) and import it in Vercel. Leave Framework Preset as **Other**; `vercel.json` sets the build.
2. Project → Settings → Environment Variables (Production):
   - `DJANGO_SECRET_KEY` = output of `python3 -c "from django.core.management.utils import get_random_secret_key as k; print(k())"`
   - `DJANGO_ALLOWED_HOSTS` = `yourname.store,www.yourname.store`
3. Project → Settings → Domains → add `yourname.store` (and `www.yourname.store`, set to redirect to the apex).
4. At your .store registrar's DNS settings, add the records Vercel shows, typically:
   - `A` record, host `@`, value `76.76.21.21`
   - `CNAME` record, host `www`, value `cname.vercel-dns.com`

   (Or switch the domain's nameservers to `ns1.vercel-dns.com` / `ns2.vercel-dns.com`.) Vercel issues the HTTPS certificate automatically once DNS resolves.
5. Redeploy after changing environment variables.

## What makes it BANDRIP (not a DICH replica)

- **Opening:** spray the BANDRIP stencil onto a graffiti brick wall with the Blender spray can (hold, or Enter); paint drips, then wet paint covers the screen. No ring, no counter screen.
- **Page transitions:** wet paint runs down and drains away (`frontend/ui/drips.js`) instead of DICH's block mosaic.
- **Hero:** a real-time GPU smoke simulation (`frontend/scenes/fluid.js`). Move the cursor to stir it; hold the mouse to spray red paint into it.
- **Mascot:** matches the supplied logo: sculpted skull, cowboy hat and bandana mask (client-supplied CC BY models fitted in Blender), baked bone textures.
- **Scroll moments:** paint drips from each chapter into the next; the identity wall gets a tag sprayed on as you scroll; THE DROP chapter sprays graffiti onto a hoodie in 3D as you scroll while the spray can tracks the spray front; a skater rolls into the footer.
- **Street layer:** brutalist walls built from CC0 brick/concrete with graffiti generated by a spray-paint simulator (`tools/graffiti/`), stickers, tape, wheat-pasted posters, stencils, the logo skull as a sprayed stencil.

## Rebuilding generated assets (optional)

Everything needed to run is already in `static/`. To regenerate (Blender 5.2 at its default Windows path):

```bash
python tools/process_photos.py                         # grade + resize photography, rebuild web/data/photos.json
python tools/mascot/textures.py                         # bandana paisley + cap patch textures
python tools/mascot/build_mascot.py                     # SDF sculpt of skull, teeth, cap, glasses, bandana (~3 min)
blender --background --factory-startup --python tools/mascot/assemble_logo.py    # logo mascot: skull + hat + bandana, bake, mascot.glb
blender --background --factory-startup --python tools/mascot/accessories.py      # cap + shades for the Depot
python tools/graffiti/make_graffiti.py                  # spray-paint kit + graffiti walls (~1 min)
python tools/props/spraycan.py --label && blender --background --factory-startup --python tools/props/spraycan.py
blender --background --factory-startup --python tools/user_glb/process.py        # hoodie, crew, skater from client GLBs
blender --background --factory-startup --python tools/mascot/render_haze.py      # hero backdrop (then convert to WebP)
python tools/depot/build_depot.py
blender --background --factory-startup --python tools/depot/blender_depot.py     # depot.glb
python tools/runway/build_walker.py
blender --background --factory-startup --python tools/runway/blender_walker.py   # walker.glb (rig + walk cycle)
node tools/capture_poster.mjs assets_src/mascot/poster_web.png                   # poster from the live scene
```

## Known limitations

- **Brand assets**: no vector logo was supplied. The wordmark is set in Anton (`templates/partials/wordmark.html`) and the mascot is an interpretation. Replace both when originals arrive.
- **Content**: product names, fabric specs, recruitment and training details, store addresses, emails and social handles are placeholders and labelled as such on the pages.
- **Forms**: validated on the client and the server, then discarded. Nothing is stored or emailed. The success states say so.
- **Runway figures** are stylised faceless mannequins with a procedural walk. They are not motion-captured humans; foot contact is approximate. Licensed rigged characters (e.g. scanned models) can replace `walker.glb` without code changes beyond material names.
- **Garment objects** are stylised "inflated" forms, built to read clearly at a distance, not as product-accurate 3D.
- **Client-supplied models** are CC BY 4.0 and must stay credited (they are, on `/about/#credits`). The `creative_commons_cap.glb` download is under the Sketchfab Standard licence, not CC BY, and was not used.
- **Home uses two WebGL contexts:** the hero smoke simulation and the 3D stage. The smoke must sit behind the headline while the mascot sits in front of it. The smoke pauses when the hero is off-screen.
- **References**: DICH's own 3D figure (a Spline scene) never finished streaming in our captures, so its exact motion was not observed; its transitions were measured frame by frame. Miu Miu's room navigation was observed only up to the first room. See `REFERENCE_ANALYSIS.md`.
- **Performance numbers** below are from headless Chrome on this machine's GPU (RTX 5070). They are not real-device measurements; a mid-range phone will be slower. Mobile already uses lower DPR, fewer walkers and no antialiasing.
- **Audio**: none.

## What was verified

`tools/verify.mjs` (Playwright driving the system Chrome) runs against the local server:

- Every route at 1440×900 and 390×844: boots, zero console errors, zero failed requests, no horizontal overflow. Screenshots of top and middle of each page.
- Gate: shows on the first visit, enters by keyboard, is skipped on later visits in the same session.
- Menu: opens with focus inside, closes with Escape, menu links navigate through the mosaic transition. The skip link is first in tab order.
- Depot: keyboard selection opens a gallery and updates the URL; browser Back returns to the explorer; Forward reopens it; the detail view opens; deep links (`/collections/pants-cargos/`) open directly; unknown categories return 404.
- Forms: an empty submit flags every required field and focuses the first; a valid submit shows the prototype success state; the server rejects invalid data with field errors (400) and accepts valid data as `prototype: true`; the contact form behaves the same.
- Reduced motion: no smooth-scroll hijack, no text scrambling, the gate still works.
- No WebGL (`--disable-webgl`): home, depot and runway show composed fallbacks with no errors.
